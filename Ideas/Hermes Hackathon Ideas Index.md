# Hermes Hackathon Ideas Index

This is the separate catalog of 93 Hermes hackathon prompts. They are reference builds and learning exercises, not part of the 48-item personal idea backlog in [[Project Ideas Index]]. The inherited `easy`, `medium`, and `hard` labels describe prototype breadth more than product value; each note now contains a local-first build boundary, recommended stack, prior art and reusable shortcuts, implementation slices, failure modes, and a path from hackathon demo to a real product.

## How to Use This Catalog

- Pick an idea for the reusable engine it teaches, not merely the headline.
- Build the smallest end-to-end demo first and keep generated actions in a review queue.
- Prefer an existing API, protocol, command, or open-source component for commodity work.
- Reuse the same engine across related ideas by changing schemas, prompts, rules, and views.
- Before publishing, hosting, monetizing, or handling other people’s data, run [[Scope Expansion Checklist]].

## Practical Starting Sequence

1. Build one viral diagnostic with no integrations.
2. Build one writing desk with structured output and a review/export flow.
3. Build one Telegram bot with SQLite and scheduled reminders.
4. Build one source-backed audit pipeline with deterministic checks.
5. Only then attempt an agency crew, multi-user room, or consequential external action.

This sequence teaches the common primitives while keeping early projects finishable. A later product can combine several engines, but the hackathon prototypes should stay narrow enough to test their central promise.
