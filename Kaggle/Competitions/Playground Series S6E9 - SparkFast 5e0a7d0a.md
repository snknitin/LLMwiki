## Core Idea: Synthetic Data and the Artifact Trap

Playground Series S6E9 asks you to predict user interest in electric vehicles (`Will_Buy_EV`) using a synthetic tabular dataset [S1](https://www.kaggle.com/competitions/playground-series-s6e9). Synthetic data is generated by a statistical process that mimics real-world distributions. It preserves feature names and plausible ranges, but it lacks the messy, unstructured noise of actual field data. This creates a specific risk: the model can learn the generation rules rather than the underlying causal relationships. When the test set is generated under slightly different parameters, the learned rules break.

You must treat synthetic data as a controlled environment. Your validation strategy must mirror the deployment question. If you are deploying to a new geographic region, a grouped split isolates region-specific artifacts. If you are deploying to a future time window, a temporal split isolates distribution drift. Stratifying by group preserves class ratios within folds, but it does not hold a group out of training. Holding a group out is the only way to measure generalization to unseen populations.

AUC is the evaluation metric for this competition [S1](https://www.kaggle.com/competitions/playground-series-s6e9). AUC measures ranking quality. It asks whether the model assigns higher predicted probabilities to positive examples than to negative examples, regardless of the decision threshold. It is robust to class imbalance. A model that predicts 0.9 for all positives and 0.1 for all negatives achieves a perfect AUC, even if the probabilities are poorly calibrated. Calibration requires separate post-processing or loss functions like `binary_crossentropy` with Platt scaling or isotonic regression.

Model selection requires a development set split into training and validation folds. Preprocessing (scaling, imputation, encoding) must be fitted on the training folds only, then applied to the validation folds. Fitting preprocessing on the full dataset leaks information. Validation performance estimates generalization within the development set. You reserve a final test set for one evaluation after all model choices are made. Cross-validation on the final test set invalidates it.

A gap between training and validation performance does not prove a unique cause. It indicates variance, but the source could be overfitting, noisy labels, or a validation split that is too easy. No universal 5% overfitting threshold exists. You must measure what matters for your deployment. If validation AUC is 0.85 and test AUC is 0.78, the delta is 0.07. That delta does not guarantee a score improvement in submission. It only suggests distribution shift or artifact leakage.

Negative R-squared on a regression task means the model performs worse than the applicable mean baseline on that evaluation set. It does not mean the model is fundamentally broken; it means the baseline is a stronger predictor for that specific metric and dataset.
