## Article Content

in Flightplan #1 I stood up an always-on agent on a box I had to keep alive myself, a cheap VPS or the Mac Mini on my desk, and the fiddly part was the box. the hardening, the tmux session, the systemd unit or the launchd watchdog, the reboot test. the whole last third of that guide was keeping the thing running.

****Hermes Cloud**** takes that third away. you pick a size in a browser, the instance comes up in seconds, and there is no ssh, no service to install, no reboot to survive because the box staying up is now someone else's job. what you do instead is the interesting part: give the agent a way to talk to you, and give it a workspace you can code in.

this is the route I took, verified on my own instance. I stood up a Small instance, wired it to Discord as my daily-chat lane, and pointed Hermes Desktop at it as a remote backend so I have a proper coding front end against the same agent. one instance, two front doors. everything below ran on that instance.

### what you will have at the end

- a hosted Hermes Agent on its own cloud instance, running around the clock, with its own dashboard and persistent workspace
- a Discord bot you message from anywhere, locked to your own account only
- Hermes Desktop on your laptop connected to that same instance as a remote backend, so your coding sessions run server-side on the cloud box
- no box to harden, no service to keep alive, no reboot to test

### before you start

you need a Nous Portal account with some credit on it, a Discord account, and Hermes Desktop installed on your laptop for the coding lane. that is the whole list. there is no ssh key this time, and no model API key to keep in a file, because on Cloud the model and inference are Portal-native.

https://x.com/witcheer/article/2076345051198984637/media/2075475021128945664### step 1: provision the instance

in Nous Portal, go to Hermes Cloud and create an instance. the form is short. you give it a name, choose a model to start with (you can change it later from the dashboard), and pick a size.

the three sizes, with the prices straight off [portal.nousresearch.com/info](https://x.com//portal.nousresearch.com/info)

:

- ****Small****, 5 concurrent sessions, 1GB RAM, 2 vCPUs. running $0.32/day, stopped $0.06/day.
- ****Medium****, 10 concurrent sessions, 2GB RAM, 4 vCPUs. running $0.59/day, stopped $0.06/day.
- ****Large****, 20 concurrent sessions, 4GB RAM, 8 vCPUs. running $1.12/day, stopped $0.06/day.

you can change size later, so pick what feels right today. I took Small. "running" is compute plus storage while the instance is on; "stopped" is storage only, which keeps your data between sessions. both are deducted from your credit hourly, and both exclude inference and tool cost, which bill separately. the cost section at the end breaks that down.

https://x.com/witcheer/article/2076345051198984637/media/2075476227767291904hit create. the instance card goes to a "starting" state, which it warns can take a couple of minutes, then flips to: "online". the card now shows the size and when it was created. now you can open the dashboard.

https://x.com/witcheer/article/2076345051198984637/media/2075476427588186112### step 2: read the dashboard

Open Dashboard takes you to the instance's own web admin panel at its HTTPS address, gated behind your Nous login. this is the whole Hermes Agent dashboard, and it is the reason there is no ssh: everything you would have done over a terminal on a self-hosted box, you do here. the left nav runs through ****CHAT, SESSIONS, FILES, MODELS, LOGS, CRON, SKILLS, PLUGINS, MCP, CHANNELS, WEBHOOKS, PAIRING**** and more, and there is a system panel showing the gateway status, active sessions, and a Restart Gateway button.

worth clicking into CHAT once to see it is a real, full agent: it lists its available tools and skills, shows the model live, and the working directory is /opt/data. that path matters, and it comes back in the Desktop step: on a Cloud instance the agent's home is /opt/data, a persistent mount that survives restarts. (I know it is /opt/data because I checked it on the instance itself, not because a doc told me.)

https://x.com/witcheer/article/2076345051198984637/media/2075476660523061249with the instance up and the dashboard open, you have two front doors to wire. lane A is Discord, for daily chat. lane B is Hermes Desktop, for coding. do either or both.

### step 3, lane A: wire Discord as your daily-chat lane

this lane has a prerequisite that lives on Discord's side, not Hermes', and it contains the single most common way to get this wrong.

on the Discord Developer Portal:

1. ****New Application****, and name your bot. mine is called Daffy.
2. open the ****Bot**** tab and turn ****Public Bot**** on.
3. still on the Bot tab, under ****Privileged Gateway Intents****, enable ****Message Content Intent**** and ****Server Members Intent****.

without Message Content Intent the bot will connect, show up online, and then read every message as empty. it looks like it is working and it is deaf. turn it on now and save yourself the debugging session.

1. under ****Installation****, use Guild Install, take the Discord-provided invite link with the bot and applications.commands scopes, and invite the bot to a personal or test server. not a server that matters, and never a shared community server, because this bot is about to get tool access.
2. turn on Developer Mode in Discord, right-click your own name, and Copy User ID. that number is your allowlist.

now back on the instance dashboard, go to CHANNELS. it lists every messaging platform Hermes can connect, each disabled, each with a Configure button, and a line telling you credentials are written to /opt/data/.env and take effect on the next gateway restart. find Discord and hit Configure. the form has: the bot token (required), the allowed user IDs (comma-separated), a reply mode (off, first, or all, defaulting to first), an allow-all-users toggle, and the home channel fields for where cron and notifications get delivered.

https://x.com/witcheer/article/2076345051198984637/media/2075477031802875904fill it in like this:

- ****bot token:**** mint it last. on the Discord Bot tab, Reset Token, copy it once, and paste it straight into this field. never into a chat, a note, or another box.
- ****allowed users:**** your Discord user ID from step 5.
- ****reply mode:**** first is fine.
- ****allow all users:**** ****false.**** this is not optional. a Discord bot on a Hermes instance has the agent's full tool and terminal access behind it, so an open bot is an open shell. keep it allowlist-only.

https://x.com/witcheer/article/2076345051198984637/media/2075477528215523328Save and Enable, then Restart Gateway from the system panel. the bot flips online in your server, and a direct message to it gets a reply. that reply is also your proof that Message Content Intent is on, because a deaf bot cannot answer.

### step 3, lane B: point Hermes Desktop at the instance

this is the coding lane. Hermes Desktop normally runs its own local agent backend on your laptop, but you can point it at a backend running somewhere else instead, and your Cloud instance is exactly that somewhere else.

install and open Hermes Desktop. on first launch it bootstraps its own local backend, and it may cycle its updater a few times to pull itself up to the current release; let it settle. then go to ****Settings → Gateway → Remote gateway****.

a Cloud instance is fronted on 443 behind a reverse proxy, so the Remote URL you enter is the plain instance HTTPS address, the same one the dashboard opens at, with no :9119 on the end.

https://x.com/witcheer/article/2076345051198984637/media/2075477716015407105for authentication the app detects that the backend uses OAuth and shows a ****Sign in with Nous Research**** button. sign in with the same Nous account that created the instance, then Save and reconnect. the app drops its local backend and attaches to the cloud one; you will see it connect to the remote Hermes backend and report ready.

because you are the instance owner, signing in with your own Nous identity, there is no approval step. verify it by asking Desktop something only the instance can answer, like what version it is running. the tool calls execute server-side on the cloud instance, not on your laptop, and the answer reflects the instance. the dashboard's SESSIONS tab will show your Desktop session appear. you now have a native coding UI on your laptop driving an agent that lives in the cloud.

### verify your setup

1. the instance card in Portal reads online, Running, Healthy.
2. the dashboard opens at the instance URL and the system panel shows the gateway running.
3. your Discord bot answers a direct message from you, and ignores anyone not on your allowlist.
4. Hermes Desktop, set to the plain instance HTTPS URL, connects as a remote backend and a test question runs server-side on the instance.
