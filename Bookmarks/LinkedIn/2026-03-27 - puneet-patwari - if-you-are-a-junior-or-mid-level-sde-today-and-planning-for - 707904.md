# If you are a Junior or Mid-level SDE today, and planning for a switch to a FAANG+ company & a salary...

> **Source:** [Puneet Patwari](https://www.linkedin.com/in/ACoAABGM0nUB-C69ft2aqKJGD5BdH7NDvJXinhw) · Principal Software Engineer @Atlassian| Ex-Sr. Engineer @Microsoft || Sharing insights on SW Engineering, Career Growth & Interview Preparation · 4mo

> [View post on LinkedIn](https://www.linkedin.com/feed/update/urn:li:activity:7443272754675707904/)

## Post

If you are a Junior or Mid-level SDE today, and planning for a switch to a FAANG+ company & a salary bump of over 50%, please focus on these system design fundamentals seriously.

This will keep your skills sharp. The market may be rough, but the only thing you truly control is how good you become.

Now, based on where you stand:

[1] If you are a Junior SDE (0–2 years)
Your focus should be on core backend and database foundations:

-- API fundamentals
-- HTTP basics
-- CRUD operations
-- Idempotency
-- SQL fundamentals
-- Data modeling basics
-- Indexing
-- Transactions
-- Basic async behavior

Btw, if you want to focus more deeply on your system design fundamentals, you can check out my guide here: puneetpatwari.in

It covers:
• 90+ important fundamental concepts
• 90+ cheatsheets for easy access
• In-depth explanations without overwhelm

Your goal at this stage is simple:
Build things that work correctly.
Understand how data flows.
Stop being scared of databases.

Do not jump into distributed systems before this is strong.

[2] If you are a Mid-level SDE (2–5 years)
This is where real system design actually starts:

-- Caching strategies
-- Concurrency handling
-- Asynchronous processing
-- Replication techniques
-- Consistency guarantees
-- Data partitioning
-- Event-driven patterns
-- Queueing strategies
-- Retry mechanisms
-- Load balancing basics

At this stage, you are no longer judged on “does it work”.
You are judged on:

-- Does it scale
-- Does it fail safely
-- Does it overload gracefully

[3] If you are targeting Senior and beyond (5+ years)
Now your thinking must move to cloud and distributed systems + system thinking:

-- CAP theorem tradeoffs
-- SLAs and SLOs
-- Multi-region design
-- Failure zones
-- Backpressure handling
-- Rate limiting design
-- Autoscaling logic
-- Observability and monitoring
-- Core VPC and networking
-- Containers and orchestration
-- AWS, GCP, or Azure deeply

Here you are paid for:

-- Preventing outages
-- Preventing cost explosions
-- Designing systems that survive failures
-- Making tradeoffs clearly and defensibly

If you want a shot at FAANG+ money:

-- Juniors must stabilize fundamentals
-- Mid-level must master scale and failure
-- Seniors must own cloud, cost, and resilience
