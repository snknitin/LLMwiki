# I use Claude Code to write code.

> **Source:** [Paolo Perrone](https://www.linkedin.com/in/ACoAAAWy1ToBOCCi0ildR12MNTXMvqvygTADf6c) · Shipping Production AI: Agents, Inference, GPU. Read by 1M+ AI engineers. · 4mo

## Post

I use Claude Code to write code.

I use Codex to review it.

Most engineers think you have to pick one. That's the WRONG approach.

Here's why the dual-model workflow ships better code:

Claude Opus 4.5 is the best code GENERATOR I've used. Fast, collaborative, incredible intent detection. It writes code the way you'd want a senior engineer to.

But it has blind spots.

Every model does. The model that wrote the code is the worst model to review it.

Same biases. Same assumptions. Same blind spots.

GPT-5.2 Codex catches bugs Claude never would.

Here's my exact workflow:

1️⃣ Claude Code: exploration
Ask questions. Understand the codebase. Build context. I spend 80% of my time here before writing a single line.

2️⃣ Claude Code: execution
Opus 4.5 with ultrathink. Closely monitored. I micro-manage the first draft and review every change in the CLI.

3️⃣ Codex: review
/review in Codex. Different model, different perspective. It finds bugs by severity: P1, P2. Fewer false positives than Claude reviewing its own work.

4️⃣ Claude Code: fix
Take the review findings back to Claude. Fix with full context.

Why this works:

Cross-model review is like getting a second opinion from a doctor who trained at a DIFFERENT hospital.

Same patient. Different diagnostic framework. Catches what the first one missed.

The pattern holds across tasks:

⚡ Claude for writing → GPT for reviewing
⚡ Claude for planning → GPT for poking holes
⚡ Claude for explaining → GPT for fact-checking

One model writes. Another model audits. Neither trusts itself.

$20/month for Claude. $20/month for Codex. $40 total.

That's cheaper than a SINGLE bug in production.

Are you still using one model to review its own code? 👇
