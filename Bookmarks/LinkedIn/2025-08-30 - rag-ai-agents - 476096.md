## Post

I’m a data scientist who self-taught RAG + AI Agents and has been shipping them in prod for a year.
If I were starting from scratch, I’d start here 👇

0 → Production RAG in 6 weeks (free).
Zero to RAG → build a real AI Research Assistant
Process 1,000+ papers on a local GenAI stack 
(and adapt it to any domain).

🔹 𝗪𝗵𝘆 𝘁𝗵𝗶𝘀 𝗺𝗮𝘁𝘁𝗲𝗿𝘀
Thousands of AI papers drop monthly - most people can’t keep up. I was the same.
So we built a production-grade RAG system to be our research copilot.
Real problem. Real solution. Real constraints.

🔹 𝗪𝗵𝗮𝘁 𝘄𝗲’𝗿𝗲 𝗯𝘂𝗶𝗹𝗱𝗶𝗻𝗴 (𝗽𝗿𝗼𝗱𝘂𝗰𝘁𝗶𝗼𝗻 𝗽𝗮𝘁𝘁𝗲𝗿𝗻𝘀, 𝗻𝗼𝘁 𝗱𝗲𝗺𝗼𝘀)

1️⃣ 𝗠𝗼𝗱𝗲𝗿𝗻 𝗣𝘆𝘁𝗵𝗼𝗻 𝘀𝘁𝗮𝗰𝗸
→ uv for fast, reproducible installs • FastAPI (async) + Python 3.12
→ Docker Compose → one-command dev setup

2️⃣ 𝗗𝗮𝘁𝗮 𝗽𝗶𝗽𝗲𝗹𝗶𝗻𝗲
→ Airflow schedules & orchestrates arXiv ingestion
→ Docling for scientific PDF parsing (structured sections/tables/figures)
→ Custom chunking preserves academic structure
→ Async/parallel batches (10+ papers at a time)

3️⃣ 𝗛𝘆𝗯𝗿𝗶𝗱 𝗥𝗔𝗚 𝗶.𝗲. 𝗿𝗲𝘁𝗿𝗶𝗲𝘃𝗮𝗹 + 𝘀𝘁𝗼𝗿𝗮𝗴𝗲
→ PostgreSQL + JSONB for flexible metadata & full text (staging layer)
→ OpenSearch 2.19 with BM25 + vector search
→ Ranking logic (latest-first, citations, etc.)

4️⃣ 𝗟𝗼𝗰𝗮𝗹-𝗳𝗶𝗿𝘀𝘁 𝗟𝗟𝗠 𝗶𝗻𝗳𝗲𝗿𝗲𝗻𝗰𝗲
→ Ollama (LLaMA 3.2, Mistral, etc.) - swap for any provider later
↳ control context windows & formatting

5️⃣ 𝗢𝗯𝘀𝗲𝗿𝘃𝗮𝗯𝗶𝗹𝗶𝘁𝘆 + 𝗲𝘃𝗮𝗹𝘂𝗮𝘁𝗶𝗼𝗻
→ Langfuse for tracing, latency, feedback
→ RAGAS for automated quality scoring

6️⃣ 𝗗𝗲𝘃 𝗲𝘅𝗽𝗲𝗿𝗶𝗲𝗻𝗰𝗲
→ Ruff + MyPy + Pre-commit + Makefile
→ Pytest with fixtures & DI overrides

7️⃣ 𝗙𝗿𝗼𝗻𝘁𝗲𝗻𝗱
→ Gradio or Streamlit for upload/search (minimal, fast, beginner-friendly)

𝗧𝗵𝗲 𝗯𝗲𝘀𝘁 𝗽𝗮𝗿𝘁:
Reuse this architecture anywhere:
→ financial reports 
→ company knowledge bases 
→ legal assistants 
→ custom scrapers
Same building blocks, different data.
