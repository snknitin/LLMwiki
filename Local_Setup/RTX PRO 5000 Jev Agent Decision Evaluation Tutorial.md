# RTX PRO 5000 Jev Agent Decision Evaluation Tutorial

Status: source review and Windows evaluation plan, 2026-09-28. Jev is a **hosted TypeSafe AI API**, so this is an opt-in comparison with local Laya and existing deterministic routing. No key, SDK, agent skill, or Hermes plugin has been installed by this note.

## Choose one real decision to test

Jev takes a state plus typed questions and returns `choice`, `score`, or `noul` probability results; it does not generate prose. TypeSafe's [official introduction](https://docs.typesafe.ai/introduction) recommends small, atomic questions and combining results in code. A good first Windows case is deciding which of three non-sensitive Local Setup notes should be opened for a user question. A second case is whether a failed local tool call should be retried, diagnosed, or escalated. Keep “delete/stop/restart” actions under deterministic policy and human review while evaluating the classifier.

The Social Capture batch links [Laya](https://github.com/NandhaKishorM/laya), [Jev research](https://academy.dair.ai/resources/jev-decisions-in-a-pi-sdk-harness), and a [Hermes Jev skills repository](https://github.com/kerpopule/hermes-jev-skills). They are different things: Laya weights run locally, Jev calls TypeSafe's API, and `hermes-jev-skills` is an optional integration layer. The maintained Hermes installation and authoritative profiles are on Spark, so a Windows SDK trial does not configure Spark Hermes. See [[RTX PRO 5000 Laya Decision Model Tutorial]] for the local side of the comparison.

## Windows trial: Playground, then API

1. Create 50–100 synthetic or redacted examples with trusted labels: relevant note, recovery path, or task tier. Freeze an untouched test set. Include ambiguous and negated wording. Record the existing deterministic route's accuracy and time first.
2. Use the [official TypeSafe Playground](https://console.typesafe.ai) with synthetic examples to confirm that the question shape works. Keep one atomic decision per question and combine the answers with deterministic code. TypeSafe's [quick start](https://docs.typesafe.ai/introduction/quickstart) shows a `noul` example and the JSON schema.
3. If API comparison is wanted, create a dedicated Python 3.11 environment on **Windows** (`py -3.11 -m venv .venv`; then `.\.venv\Scripts\python.exe -m pip install typesafe-sdk`). The [official SDK guide](https://docs.typesafe.ai/introduction/quickstart) uses `TypeSafeClient`, which reads `TYPESAFE_API_KEY` from the environment. Obtain a key in the TypeSafe console and set it in the local shell's secure process environment without pasting it into chat or a vault note. Send only the synthetic/redacted test state.
4. Use the same state, question wording, and labels for Jev and Laya where supported. Record each response's model version, answer, full probability vector, confidence/abstention decision, API round-trip time, and any error. Do not compare Laya's compute latency with Jev's network round-trip as though they were the same resource; report both end-to-end wall time and decision quality. Batch only when the API and workflow support it; measure serial and batched cost separately.
5. For an optional shadow integration, inspect [Hermes Jev skills](https://github.com/kerpopule/hermes-jev-skills) and its [shadow-to-live guide](https://github.com/kerpopule/hermes-jev-skills/blob/main/docs/shadow-to-live.md). The repository documents `python install.py --check` as a dry-run. On this setup, make a separate Spark-specific decision before enabling the plugin because Spark owns Hermes profiles and private routes.

## Acceptance gate

Compute per-class accuracy, false positive/negative counts, calibration by probability bucket, abstention coverage, p50/p95 latency, API cost per 1,000 cases, and full task wall time. Set an escalation threshold on development data, then evaluate once on the frozen test set. Check order bias on pairwise judgments by asking both candidate orders; the [JEV-as-a-Judge paper summary](https://academy.dair.ai/papers/jev-as-a-judge-accept-when-confident-escalate-when-unsure-2609.26550) calls this out. Any confidently wrong decision that would perform a destructive action fails autonomous promotion. On failure, retain the deterministic route and save the labelled examples for another model or question design.
